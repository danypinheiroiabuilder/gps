# Fase 00 — Descoberta

## 1. Por que essa fase existe?

Antes de investir em produto, arquitetura ou código, é preciso confirmar que o problema é real, quem sente a dor e se vale a pena abrir um projeto. Esta fase evita construir a solução certa para o problema errado — ou pior, construir sem problema nenhum.

## 2. Quais perguntas preciso responder?

- Qual problema estamos tentando resolver e para quem?
- Como as pessoas resolvem isso hoje (gambiarras, planilhas, processos manuais)?
- Qual é o custo de não resolver (tempo, dinheiro, risco, frustração)?
- Há evidência concreta (conversas, dados, reclamações) ou só uma hipótese?
- O que está fora de escopo desde o início?
- Quem decide se o projeto segue ou para?
- Existe restrição de prazo, orçamento ou conformidade que já invalida algumas abordagens?

## 3. O GPS da Fase

1. Registrar o problema em uma frase clara e verificável.
2. Identificar personas / stakeholders afetados e o impacto em cada um.
3. Coletar evidências mínimas (entrevistas, tickets, métricas, observação).
4. Mapear alternativas atuais e por que falham ou são caras.
5. Definir hipótese de valor: “Se fizermos X, Y melhora porque Z”.
6. Decidir go / no-go com critério explícito e dono da decisão.
7. Registrar o resultado e apontar o próximo passo no Contexto Global (Fase 01).

## 4. Controle de Qualidade/Checklist

- [ ] Problema descrito em uma frase, sem jargão técnico desnecessário
- [ ] Público afetado identificado
- [ ] Pelo menos uma evidência documentada (não só opinião)
- [ ] Alternativas atuais mapeadas
- [ ] Hipótese de valor escrita
- [ ] Decisão go / no-go registrada com responsável
- [ ] Escopo inicial do que NÃO será feito listado
- [ ] Contexto Global (01) atualizado com o resultado desta fase
